DESCRIÇÃO COMENTADA DO CÓDIGO DA PLATAFORMA DE QUALIDADE DO AR
==========================================================

Finalidade e âmbito
------------------
Este documento descreve a implementação existente da plataforma web de
consulta e análise de dados históricos da qualidade do ar em Beja. Os caminhos
indicados são relativos à pasta do projeto que contém src/ e backend/.

A descrição resulta da leitura do código. Não constitui um relatório de testes
executados nem uma avaliação de desempenho ou usabilidade. Os comentários
assinalados como «Comentário explicativo» foram acrescentados apenas neste
documento; os ficheiros da aplicação não foram modificados. Os excertos são
segmentos do código real, pelo que não constituem programas autónomos.

O sistema recebe ficheiros CSV, trata as leituras em Python, guarda-as em
SQLite e disponibiliza-as através de Flask. A interface Vue consulta a API e
apresenta os dados em cartões, gráficos e mapas. A consulta depende dos dados
previamente importados: não existe recolha direta dos sensores em tempo real.

1.6. Cálculo do AQI demonstrativo
--------------------------------
Ficheiro: src/services/aqi.js

    for (const intervalo of intervalos) {
      const de = Math.max(intervalo.inicio, inicio)
      const ate = Math.min(intervalo.fim, fim)

      // Se existir uma lacuna ou sobreposição, não calcula.
      if (de !== cursor || ate <= de) {
        return null
      }

      // A concentração é ponderada pela duração.
      somaPonderada += intervalo.valor * (ate - de)
      cursor = ate
    }

    // Só calcula se as 24 horas estiverem completas.
    if (cursor !== fim) return null

    const media24h = somaPonderada / (fim - inicio)

    return calcularAqiPm25(media24h)

Comentário explicativo:
calcularAqiIntervalo seleciona os intervalos válidos do sensor que intersectam
as 24 horas anteriores ao fim da leitura de referência. O ciclo limita cada
intervalo à janela, verifica continuidade e acumula concentração vezes duração.
O cálculo assume que cada valor representa a média do respetivo intervalo.
Não basta contar 24 linhas; a cobertura temporal tem de estar completa.

Depois de obter a média, calcularAqiPm25 trunca-a a uma casa decimal, procura
uma faixa e interpola o índice:

    const [cMin, cMax, iMin, iMax] = faixa

    // Interpolação linear para calcular o índice.
    return Math.round(
      ((iMax - iMin) / (cMax - cMin)) *
      (c - cMin) + iMin
    )

Comentário explicativo:
O resultado é um índice sem unidade. As faixas são demonstrativas no código;
este cálculo não deve ser apresentado como índice oficial português nem como
avaliação de conformidade legal. A origem e validação das faixas devem ser
documentadas: \textbf{[INFORMAÇÃO A COMPLETAR]}.

App.vue mantém a função aqiNoInstante, sem chamadas identificadas, que referencia
calcularAqiPm25 sem o importar. O percurso ativo do indicador e do mapa utiliza
calcularAqiIntervalo; a função antiga não deve ser descrita como funcionalidade ativa.


2. BACKEND
==========

2.1. Aplicação Flask e separação de responsabilidades
---------------------------------------------------
Ficheiro: backend/app.py

    from database import ligar, inicializar, listar_leituras
    from csv_parser import extrair_transformar, CAMPOS

    from flask import Flask, request, jsonify
    from flask_cors import CORS

    app = Flask(__name__)

Comentário explicativo:
Flask associa pedidos HTTP às funções Python. request permite aceder aos
parâmetros e ficheiros recebidos; jsonify serializa os resultados para JSON.
O parser concentra a transformação, database.py concentra o acesso relacional
e app.py coordena os pedidos e a inserção. A carga do ETL está implementada em
app.py, pelo que esta separação é modular, mas não corresponde a uma camada
de serviços totalmente independente das rotas.

inicializar() é chamada quando o módulo é carregado. Cria o esquema necessário
e recusa determinados esquemas antigos incompatíveis. Importar app.py pode,
portanto, provocar acesso à base de dados.

2.2. Consulta das leituras
-------------------------
Ficheiro: backend/app.py

    @app.get('/api/leituras')
    def leituras():
        argumento = request.args.get('sensor', 'todos')
        if argumento != 'todos' and not argumento.isdecimal():
            return jsonify({'erro': 'sensor_id deve ser um número inteiro'}), 400
        with ligar() as db:
            resultado = listar_leituras(db, None if argumento == 'todos' else int(argumento))
        return jsonify(resultado)

Comentário explicativo:
O decorador regista a rota GET. O parâmetro sensor é opcional e assume todos.
Um valor que não seja todos nem uma representação decimal recebe HTTP 400.
A consulta delega a construção SQL a listar_leituras. Não existe nesta rota
paginação nem filtragem por datas; todos os registos correspondentes são devolvidos.

Ficheiro: backend/database.py

    if sensor is not None:
        sql += ' WHERE l.sensor_id = ?'
        parametros.append(sensor)
    sql += ' ORDER BY l.timestamp_init_UTC, l.reading_id'
    return [dict(r) for r in db.execute(sql, parametros)]

Comentário explicativo:
O marcador ? separa o valor do parâmetro da estrutura SQL. A ordenação utiliza
o início UTC e o identificador da leitura. A consulta também devolve os aliases
data, lat e lng, usados pelos componentes existentes, sem duplicar essas colunas
na tabela física.

2.3. Ligações e integridade relacional
-------------------------------------
Ficheiro: backend/database.py

    def ligar():
        conexao = sqlite3.connect(DB_PATH)
        conexao.row_factory = sqlite3.Row
        conexao.execute('PRAGMA foreign_keys = ON')
        return conexao

Comentário explicativo:
DB_PATH aponta para qualidade_ar.db junto de database.py. sqlite3.Row permite
aceder às colunas pelo nome. A ativação das chaves estrangeiras em cada ligação
faz com que o SQLite aplique as relações declaradas.

O modelo contém:
- sensores: identificação, nome, coordenadas e metadados;
- ficheiros: nome único, sensor associado e data de importação;
- leituras: sensor, ficheiro de origem, quatro marcas temporais e quinze campos
  numéricos, incluindo treze medições e duas coordenadas.

Excerto das restrições da tabela leituras:

    FOREIGN KEY(sensor_id) REFERENCES sensores(sensor_id),
    FOREIGN KEY(ficheiro_id) REFERENCES ficheiros(id) ON DELETE CASCADE,
    CHECK(timestamp_end_UTC > timestamp_init_UTC),
    UNIQUE(sensor_id, timestamp_init_UTC, timestamp_end_UTC)

Comentário explicativo:
As chaves estrangeiras relacionam leituras com sensores e ficheiros existentes.
CHECK exige fim posterior ao início na representação temporal normalizada.
UNIQUE impede repetir exatamente o mesmo intervalo para o mesmo sensor.
Não impede, por si só, intervalos diferentes que se sobreponham.

    CREATE INDEX IF NOT EXISTS idx_leituras_sensor_tempo
        ON leituras(sensor_id, timestamp_init_UTC);

Comentário explicativo:
O índice foi definido para apoiar consultas por sensor e tempo. A sua existência
não comprova uma melhoria de desempenho medida; não foram executadas medições
para este documento.

3. COMUNICAÇÕES
===============

3.1. Serviço Axios e contrato HTTP
---------------------------------
Ficheiro: src/services/airService.js

    const api = axios.create({ baseURL: 'http://localhost:5000/api' })
    export const airService = {
      async getSensores() { return (await api.get('/sensores')).data },
      async getLeituras(sensor = 'todos') { return (await api.get('/leituras', { params: { sensor } })).data },
      async uploadCSV(files) {
        const form = new FormData()
        for (const file of files) form.append('ficheiros', file)
        return (await api.post('/upload', form)).data // Axios define o boundary automaticamente.
      },
      async limparDados() { return (await api.delete('/dados')).data }
    }

Comentário explicativo:
O serviço centraliza os endereços e pedidos, evitando distribuir chamadas HTTP
pelos componentes visuais. async/await permite aguardar as respostas sem bloquear
a interação do navegador. response.data contém o corpo devolvido pela API.

Contrato identificado:
- GET /api/sensores: lista os sensores;
- GET /api/leituras? sensor=...: consulta leituras; o endereço real não contém
  espaço entre ? e sensor, sendo os parâmetros construídos pelo Axios;
- POST /api/upload: recebe ficheiros num formulário multipart;
- DELETE /api/dados: elimina os dados importados.

O upload utiliza multipart/form-data, não um corpo JSON. O nome ficheiros tem
de coincidir com request.files.getlist('ficheiros') no Flask. As respostas das
rotas são JSON. O boundary separa as partes do formulário e é definido pelo
navegador/Axios no envio de FormData.

A baseURL é fixa e local. A configuração de um endereço de produção ou de
ambientes distintos constitui uma evolução possível, não implementada aqui.

4.2. Normalização e conversão numérica
-------------------------------------
Ficheiro: backend/csv_parser.py

    def normalizar_cabecalho(nome):
        # Ex.: "NO2(µg/m³)" -> "no2"; evita confundir PM1 e PM10.
        return nome.strip().split('(')[0].strip().lower()

Comentário explicativo:
A função remove espaços exteriores e a unidade entre parênteses, convertendo

    def numero(valor):
        if valor is None or not str(valor).strip():
            return None
        n = float(str(valor).strip().replace(',', '.'))
        if not math.isfinite(n):
            raise ValueError('Número não finito')
        return n

Comentário explicativo:
Campos vazios originam None, que sqlite3 guarda como NULL. Substituir a vírgula
decimal permite converter números que a utilizem. NaN e infinitos são rejeitados.
O código não substitui medições ausentes por zero, nem realiza imputação.

4.3. Datas, fusos horários e coerência temporal
---------------------------------------------
Ficheiro: backend/csv_parser.py

    def data_iso(valor):
        if not valor or not str(valor).strip():
            return None
        data = datetime.fromisoformat(str(valor).strip().replace('Z', '+00:00'))
        if data.tzinfo is None:
            raise ValueError('Timestamp sem fuso horário')
        return data

Comentário explicativo:
As datas têm de incluir informação de fuso horário. Z é convertido para a
representação equivalente +00:00. Posteriormente, início e fim são normalizados
em UTC e guardados com precisão de milissegundos.

    zona = ZoneInfo('Europe/Lisbon')
    for chave, instante in [('timestamp_init_Europe_Lisbon', inicio),
                           ('timestamp_end_Europe_Lisbon', fim)]:
        informado = data_iso(bruto.get(chave))
        if informado and abs((informado - instante).total_seconds()) > 1:
            raise ValueError(f'{chave} incoerente com UTC')
        reg[chave] = instante.astimezone(zona).isoformat(timespec='milliseconds')

Comentário explicativo:
As datas locais são recalculadas com as regras Europe/Lisbon. Se o CSV incluir
um instante local divergente do UTC em mais de um segundo, a linha é rejeitada.
A comparação verifica o instante representado; o valor guardado é sempre o
resultado da conversão para Lisboa.

4.5. Carga transacional e identificação do sensor
------------------------------------------------
Ficheiro: backend/app.py

    nome_sensor = Path(nome).stem
    reg = db.execute('SELECT sensor_id FROM sensores WHERE nome=?', (nome_sensor,)).fetchone()

Comentário explicativo:
Na ausência de sensor_id explícito no formulário, o nome do sensor é derivado
do nome do ficheiro sem a extensão. O identificador inteiro é gerado pelo
SQLite. Ficheiros com nomes diferentes não são automaticamente reconhecidos
como pertencentes ao mesmo sensor físico.

Dentro do contexto transacional, o código regista o ficheiro e insere as leituras:

    fid = db.execute('INSERT INTO ficheiros(nome,sensor_id) VALUES (?,?)', (nome, sensor_id)).lastrowid
    colunas = ('sensor_id', 'ficheiro_id', *CAMPOS)
    campos_sql = ', '.join('"'+c+'"' for c in colunas)
    marcadores = ', '.join('?' for _ in colunas)
    db.executemany(f'INSERT INTO leituras ({campos_sql}) VALUES ({marcadores})',
                   [(sensor_id, fid, *[r[c] for c in CAMPOS]) for r in transformadas])

Comentário explicativo:
fid relaciona cada leitura com a importação de origem. Os nomes das colunas
provêm de constantes internas e os valores são enviados através de parâmetros.
executemany aplica a inserção às leituras transformadas.

O bloco with ligar() as db confirma a transação na saída normal e reverte-a
se uma exceção escapar do bloco. A transação abrange um ficheiro, não todo o
lote de ficheiros enviados. Uma falha pode, por isso, deixar outros ficheiros
do mesmo pedido corretamente importados. Um conflito de unicidade na carga
reverte a carga desse ficheiro, em vez de ignorar apenas a leitura em conflito.
